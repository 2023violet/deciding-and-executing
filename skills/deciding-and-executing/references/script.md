# de.py 说明

日常照每条命令输出的 `next` 走就行；这里是需要细节时查的参考。完整参数见 `de.py --help`。只用 Python 标准库（3.8+）。

## 目录
- 命令
- 文件归属
- 完成的证据规则
- 代码指纹
- 只读检查
- 其他：多个工作区、英文、退出码、没有脚本时

## 命令

| 命令 | 用途 |
|---|---|
| `init [--name] [--risk standard\|high] [--lang zh\|en]` | 建工作区；`--lang en` 生成英文模板 |
| `list` | 列出本仓库所有工作区 |
| `status` [`--brief`] | 当前阶段、确认状态、升级与下一步；`--brief` 是给会话开始钩子用的 ≤15 行纯文本 |
| `handoff` [`--json`] | 只读交接摘要：步骤与证据新鲜度、升级、假设、最近事件、下一步、文件路径 |
| `check card` / `check plan` | 只校验，不改状态 |
| `gate A` / `gate B` / `gate AB` [`--confirm`] | 确认决策卡 / 计划；`AB` 一次确认两者，仅标准档 |
| `preflight` | 只读预检：分支、未提交改动、将要执行的验证命令及其风险提示 |
| `coverage` | 只读列出成功标准与步骤证据的对应关系，不自动宣称满足 |
| `step ID --status …` | 推进步骤，受状态机与证据规则约束 |
| `verify ID` / `verify --all` | 执行验证命令，记录退出码与代码指纹；失败自动计数 |
| `fail ID --note` | 手动记录失败（没有验证命令的步骤） |
| `replan ID --note [--waive 理由]` | 解除升级：步骤必须已修改，或经用户确认记录豁免 |
| `reopen ID --reason` | 重做已完成的步骤；旧证据归档，审查结论作废 |
| `review --verdict pass\|fix\|fail [--blocker] [--independent-report]` | 记录审查结论；可关联独立复核报告 |
| `archive [--outcome 完成\|止损\|放弃] [--apply]` | 归档为决策记录，不删除任何文件（英文工作区写 `done\|stopped\|abandoned`） |
| `sync --report 文件` | 现场运行 closing-out 审计，通过后登记知识同步 |
| `closeout --report 文件 [--outcome] [--apply]` | 归档与同步一步完成：先预览，用户同意后 `--apply` |
| `purge` [`--confirm`] | 删除工作区：要求已同步、已提交到 git、只含已知文件 |
| `prove [--shell] -- <命令>` | 轻量验证：不需要工作区，运行一条命令并绑定当前代码指纹；输出已验证 / 未通过 / 未验证（非 git），不写任何文件 |

需要用户确认的命令，第一次调用只返回 `token`、`preview` 和带 `needs_user: true` 的 `next`；用户同意后带 `--confirm` 重跑。token 由内容计算，内容一变就失效。它防止误操作和确认过期内容，但证明不了确认的是人。

## 文件归属

`plan.json` 是你编写的计划结构；状态、证据、确认记录和审查结论在 `state.json`，只由脚本写入，每次写入的摘要记在 `events.jsonl`。`plan.json` 里出现的运行时字段会被忽略；`state.json` 在脚本之外被改动时，`status` 会报警。这能挡住疏忽和随手修改，挡不住有意同时伪造两份文件。

## 完成的证据规则

- 步骤有验证命令：脚本当场执行，退出码 0 且执行期间代码没变才算完成，任何文字都替代不了。
- 没有验证命令：`--artifact 文件`，记录哈希；审查和以"完成"归档时会重新核对文件、哈希与代码指纹。
- 标准档还可以 `--evidence 文字`，记为"未验证"，在状态、审查和决策记录里单独标出。高风险档不接受文字证据。
- 验证命令优先写 `verify_argv`（参数数组，不经 shell，各系统一致）；需要管道或重定向时才写 `verify_cmd`（交给系统 shell，Windows 上是 cmd.exe）。二者只能写一种。

## 代码指纹

覆盖 Git 已跟踪的改动，加上未跟踪文件的路径和内容（单文件 32 MiB、总量 128 MiB 上限，超限拒绝验证）；**不含被 Git 忽略的文件**。步骤依赖忽略文件（本地配置、外部设备、环境变量）时，另给可验证的证据，不要宣称"仓库全部文件均已验证"。代码改过之后，旧的命令证据就不对应当前代码了，审查前要 `verify --all`。

## 只读检查

- `preflight`：执行前看当前分支、未提交改动和将要执行的验证命令，不要自动清理用户的改动。
- `coverage`：审查时把编号成功标准逐条与实际证据比对；缺少 GUI、硬件或人工观察时保留 `NOT_VERIFIED`。
- 验证命令不是安全的沙箱：确认计划和 `preflight` 里的风险提示是不完整的模式匹配，没命中不等于安全；高风险操作仍需宿主授权与隔离环境。

## 其他

- **一个仓库多件事**：每件事一个工作区（如 `init --dir .decision-<名称>`），之后每条命令带同一个 `--dir`，或设置环境变量 `DE_WORKSPACE`；`list` 列出全部。代码指纹排除所有工作区，互不影响。
- **英文用户**：`init --lang en` 生成英文模板；决策卡的章节、字段和结论接受英文写法（Goal、Success criteria、Verdict: go / go with changes / drop 等）。`next`、`--brief` 和 `handoff` 按工作区语言输出；其他提示仍是中文。
- **非 git 项目**：能用，但证据无法绑定当前代码，失败不自动计数，`purge` 拒绝删除工作区。
- **退出码**：0 成功；1 检查未通过；2 用法或数据错误；3 被拒绝或需要确认（看 `reason`）。
- **没有代码执行环境时**：按 `assets/` 模板在回复里输出决策卡和计划，按三份流程文档里的"人工检查"自检，并如实告诉用户"这次没有脚本保证"。
