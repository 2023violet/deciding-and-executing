# ⑤ 收尾：5A 归档 → 5B 知识同步 → 5C 删除工作区

**目的**：这件事结束后，不留下会误导别人的东西。决策过程变成一份历史记录；项目文档和规则文件跟上新的现状；过程文件在可恢复的前提下删除。
**进入条件**：闸门 D——审查结论为 pass 且复盘完成；或决定止损、放弃，且复盘完成。
**产出**：`docs/decisions/YYYY-MM-DD-名称.md`（含知识同步报告）；同步后的 README、docs、规则文件。

## 为什么分三步

- **5A 归档**只写决策记录，不删除任何东西；
- **5B 知识同步**由 closing-out 审计整个仓库，脚本核对审计结果没有 error、没有被截断、并且对应当前代码；
- **5C 删除**要求前两步都完成、工作区已提交到 git（删了能恢复）、只含 de.py 管理的文件，并经用户确认。

只完成 5A 不算结案。closing-out 发现阻断问题时，停在 5B 修复，不进入 5C。`status` 的 `stage` 依次显示 `closeout`（可以归档）→ `archived`（等待同步）→ `ready-to-purge`（等待删除）。

## 清单

```
⑤ 收尾
- [ ] 5A-1 archive 预览，展示给用户
- [ ] 5A-2 用户同意后 archive --apply
- [ ] 5B-1 交给 closing-out 完整档，完成影响面与源码事实核查
- [ ] 5B-2 收尾报告存为 .decision/closeout-report.md
- [ ] 5B-3 sync
- [ ] 5C-1 提交所有改动
- [ ] 5C-2 purge 预览，展示文件清单给用户
- [ ] 5C-3 用户同意后 purge --confirm
```

## 5A 归档

`python3 scripts/de.py archive --outcome 完成`（止损或放弃时相应改）。预览会列出写入位置和问题；脚本检查：
- 决策卡通过检查；复盘三节有实质内容；
- 以"完成"归档时：审查结论为 pass，且审查之后代码和计划都没有变；所有步骤 done；
- 写入位置在项目内、不在工作区里、文件不存在（不覆盖）。

用户同意后加 `--apply`。决策记录里每一步的证据都标明类型：命令（附退出码与代码指纹）、文件（附哈希）、文字（标"未验证"）。

## 5B 知识同步

安装了 closing-out 时，按它的完整档执行，并告诉它本次改过的名字（用于 `--rename`）。审计和报告保存到工作区：

```
python3 <closing-out>/scripts/audit.py [--rename 旧=新 ...]  # 可先独立预审
（按 closing-out 的模板写报告）→ .decision/closeout-report.md
python3 scripts/de.py sync --report .decision/closeout-report.md  # 本次现场重跑可信审计并保存 JSON
```

`sync` 不信任先前存放的审计 JSON，它会现场执行配套的审计脚本。拒绝的情况：本次审计退出异常、有 error、输出被截断、代码指纹不一致、项目根不一致，或报告缺失/几乎为空。通过后，报告并入决策记录，记录里的"知识同步"一行更新为已完成。

**没有安装 closing-out 时**不能运行 `sync`。至少做完下面的最小清单，并在回复中如实说明"未做脚本化的知识同步"，工作区保留不删：
- [ ] README 的功能、命令、路径与现状一致（实际运行过启动和测试命令）
- [ ] 规则文件（AGENTS.md / CLAUDE.md）没有引用不存在的路径和命令
- [ ] 复盘里"教训去向"一栏的每条教训都已放到对应位置
- [ ] 计划草稿、调试脚本、旧副本已列入删除候选

## 5C 删除工作区

1. 提交所有改动（包括 `.decision/` 和决策记录）。工作区有未提交内容时脚本拒绝删除，因为删了就无法从 git 恢复。
2. `python3 scripts/de.py purge`：返回将要删除的文件清单和 token。**把清单展示给用户，等用户回复同意。**
3. 用户同意后 `purge --confirm TOKEN`。清单一变（例如有人往工作区里放了文件），token 就失效。工作区里有 de.py 不认识的文件或目录时，脚本拒绝删除，交给用户处理。

高风险档位要求为 `purge --confirm` 配置宿主审批规则，见 [permissions.md](permissions.md)。

删除后提交，再运行一次 closing-out 审计确认没有残留。

## 会话级的轻量收尾

项目还没结束、只是一次会话结束时，不归档。本次改动如果影响了 README 或规则文件里的命令、路径、名字，交给 closing-out 的轻量档；没有安装时，至少搜一遍本次改过的名字和命令。

## 本阶段常见坑

- 只做了 5A 就宣布结案。
- 审计之后又改了文档，却拿旧的审计结果去 sync。
- 跳过归档直接删工作区：决策理由和被证伪的假设就此丢失。
- 把决策记录当成现状文档继续更新：决策记录写完就不再改，现状写在 docs。
- 在用户没看到文件清单前就带 `--confirm` 删除。
