# ① 定方向

**目的**：把模糊的想法收敛成一个明确结论（做 / 改后做 / 放弃）和一张决策卡。
**进入条件**：方向未定；几个方案拿不定；或执行中触发二级升级。
**产出**：`.decision/decision-card.md`，通过闸门 A。

## 清单（复制到回复里逐项勾选）

```
① 定方向
- [ ] 1 重述真正的问题
- [ ] 2 暴露隐含假设
- [ ] 3 找未知的未知
- [ ] 4 给 2-4 个方向
- [ ] 5 找能翻转结论的那一个假设
- [ ] 6 补信息：能查的去查，只问用户一个问题，然后等待
- [ ] 7 给结论，填决策卡，过闸门 A
```

## 步骤

**1 重述**：一两句话说出字面之下的真实困惑。用户问错了问题就直接指出该问什么——比回答错的问题有用得多。

**2 假设**：列出用户没说但默认成立的假设，标出哪几条一旦不成立结论就要推翻。这些进入决策卡的"关键假设"表，编号 A1、A2……

**3 未知的未知**：用户在这个领域可能不知道该问什么？涉及工具、技术、路径选择时，替他判断最合适的方案，而不是默认他已选对。

**4 方向**：给 2-4 个真正不同的方向，不强行分成"支持/反对"两派——二元框架会挤掉更好的第三条路。每个方向写：
- 最强论证（可验证事实与推测分开，推测标注）
- 在什么条件下它是最优解
- 代价与最大风险

不为凑数造弱方案。用户已明确收窄到 A 或 B、只想压力测试时，只分析这两个：各自的最强支持、最强反对、适用条件、最大风险。

**5 关键分歧**：各方向真正分歧在哪？"只改变一个假设就能翻转结论"的是哪一个？它就是 A1，也是计划阶段第一个要验证的对象。

**6 补信息**：环境、文件、搜索能拿到的，先自己拿。只有用户知道、且会改变结论的，才问——一次一个，附上你的推荐答案。然后**停下来等**，不要在同一条回复里替用户回答并继续。信息已经够了就跳过这步。

**7 结论**：给出
- 做 / 改后做 / 放弃（三选一）
- 最大风险
- 最缺的关键证据
- 今天能做的最小一步
- 置信度及依据

然后 `python3 scripts/de.py init --name 名称 [--risk high]`（如未初始化；档位见 SKILL.md 第 1 节），填写决策卡。注意三处格式，脚本会检查：
- `- 结论：` 后以 **做 / 改后做 / 放弃** 之一开头，补充说明放在括号里；
- 成功标准用 `1.` `2.` 编号，计划会按编号对应；
- 止损条件写成三行：`- 触发状态：…`、`- 期限：YYYY-MM-DD`、`- 动作：…`。

结论是"放弃"也要填：写清放弃理由和什么情况下值得重新考虑。

## 闸门 A

1. `python3 scripts/de.py check card`：`errors` 非空就补齐后重跑；`warnings` 逐条向用户说明，要么修正，要么让用户明确接受。
2. `python3 scripts/de.py gate A`：返回 token 和 preview（结论、成功标准、止损）。**把 preview 展示给用户，等用户回复同意**，再带 `--confirm TOKEN` 重跑。不要在同一次回复里自己确认。

之后只要目标、成功标准、非目标、止损条件或结论被改动，闸门 A 和 B 都会失效，需要重新确认；只更新关键假设的状态或修订记录不会失效。

**人工闸门清单**（无代码执行时使用）：
- [ ] 结论是三选一之一
- [ ] 目标描述结果而非动作
- [ ] 每条成功标准都能被观察或验收
- [ ] 写了非目标
- [ ] 至少一条编号假设，且标出了 A1
- [ ] 止损条件有触发状态、期限（日期）和动作
- [ ] 用户看过上述内容并明确同意

## 高风险时的独立性要求

决定难以撤回、损失大时，提醒用户：本对话里的反方论证来自同一个模型，独立性有限。建议把 A1 拿到真正独立的信源核对——另一个模型、不带上下文的新会话、或懂行的人——只给问题和证据，不给本次的结论，再比对。

## 二级升级回到这里时

只重审被击中的那条假设：它为什么失效、结论是否翻转、决策卡哪几项要改。改完在"修订记录"加一行。如果改到了目标、成功标准、非目标、止损条件或结论，重新 `gate A`，再回到②只调整受影响的步骤并重新 `gate B`。不重做整个①。

## 本阶段常见坑

- 在用户回答关键问题之前就给出最终结论。
- 给 4 个方向，其中 2 个明显是凑数的陪衬。
- 把"我觉得"写进最强论证而不标注为推测。
