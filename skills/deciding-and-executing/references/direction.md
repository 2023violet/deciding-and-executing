# 定方向

把模糊的想法收敛成一个结论（做 / 改后做 / 放弃）和一张决策卡。方向未定、几个方案拿不定、或执行中有关键假设被推翻时读这里。

## 清单（复制到回复里逐项勾选）

```
- [ ] 1 重述真正的问题
- [ ] 2 列出隐含假设
- [ ] 3 补上用户可能不知道要问的
- [ ] 4 给 2-4 个真正不同的方向
- [ ] 5 找出能翻转结论的那一个假设
- [ ] 6 补信息：能查的自己查；只问用户才知道的，按轮问，问完就等
- [ ] 7 给结论，填决策卡，请用户确认
```

## 怎么做

**1 重述**：一两句话说出字面之下的真实困惑。用户问错了问题，就直接指出该问什么。

**2 假设**：列出用户没说但默认成立的假设，标出哪几条一旦不成立结论就要推翻。它们进入决策卡的"关键假设"表，编号 A1、A2……

**3 补盲点**：用户在这个领域可能不知道该问什么？涉及工具、技术、路径选择时，替他判断最合适的方案。

**4 方向**：给 2-4 个真正不同的方向，不强行分成"支持 / 反对"两派。每个方向写最强论证（事实与推测分开，推测标注）、在什么条件下最优、代价与最大风险。不为凑数造弱方案；用户已收窄到 A 或 B 时，只分析这两个。

**5 关键假设**：只改变一个假设就能翻转结论的那条，就是 A1，也是计划里第一个要验证的。

**6 补信息**：事实归你，决定归用户。环境、文件、搜索能拿到的，先自己拿；只有用户知道、且会改变结论的，才问。信息够了就跳过。

问题按**轮**问。一个决定定下来，才能问挂在它下面的问题：
- 一轮只问前提都已确定的问题；依赖本轮其他答案的，留到下一轮。
- 每题编号，附推荐答案，措辞让用户回"是"就等于采纳推荐。
- 问完就停下等，不要替用户回答。
- 某个问题要等一个还在查的事实时，只有它和它下游的问题要等。

```
Q1 <问题标题>：<问题，可含选项>
→ 推荐：<推荐答案及一句理由>
```

**7 结论**：做 / 改后做 / 放弃，加上最大风险、最缺的证据、今天能做的最小一步、置信度及依据。结论是"放弃"也要写清理由和什么情况下值得重新考虑。

## 决策卡与确认

需要建工作区时运行 `de.py init --name 名称 [--risk high]`，填写 `.decision/decision-card.md`。脚本检查三处格式：
- `- 结论：` 以 **做 / 改后做 / 放弃** 之一开头，补充说明放在括号里；
- 成功标准用 `1.` `2.` 编号，计划按编号对应；
- 止损条件写三行：`- 触发状态：…`、`- 期限：YYYY-MM-DD`、`- 动作：…`。

然后照 `next` 走：`check card` 没有 error 后，`gate A`（或标准档的 `gate AB`）会返回预览，**把预览给用户看，用户同意后**才带 `--confirm` 重跑。

确认之后，改动目标、成功标准、非目标、关键假设的内容、止损条件、结论或失败次数上限，确认都会失效，需要重新确认；只更新假设表的"状态"列或修订记录不会。

**没有脚本可用时**的人工检查：结论是三选一；目标描述结果而非动作；每条成功标准都能被观察；写了非目标；至少一条编号假设并标出 A1；止损有状态、日期和动作；用户看过并明确同意。

## 高风险时

决定难以撤回、损失大时，提醒用户：本对话里的反方论证来自同一个模型。建议把 A1 拿到独立的信源核对（另一个模型、不带上下文的新会话、懂行的人），只给问题和证据，不给本次的结论。

## 关键假设被推翻、回到这里时

只重审被推翻的那条：为什么失效、结论是否翻转、决策卡哪几项要改。改完在"修订记录"加一行，重新确认，再只调整计划里受影响的步骤。不重做整个流程。

## 常见坑

- 用户还没回答关键问题就给最终结论。
- 四个方向里有两个明显是陪衬。
- 把"我觉得"写进最强论证而不标注为推测。
