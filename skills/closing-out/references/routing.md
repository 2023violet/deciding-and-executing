# 路由表：改了什么 → 要去哪里检查

审计脚本能找到死链、失效路径、旧名字残留；但"文档描述的行为已经变了"只能靠这张表逐项排查。对每一类本次发生过的改动，把右边列出的位置都搜一遍。

## 目录
- 变更类型路由
- 搜索技巧
- 不需要同步的情况

## 变更类型路由

| 本次改动 | 要检查的位置 | 搜什么 |
|---|---|---|
| 改名（函数、模块、文件、目录、服务、环境变量） | README、docs/、规则文件、代码注释、配置示例 | 旧名字；用 `audit.py --rename 旧=新` |
| 删除功能或模块 | README 的功能列表、docs 的使用说明、规则文件里的"不要改 X"、示例代码 | 功能名、模块路径、相关命令 |
| 新增功能 | README 功能列表、使用说明；**只有当 Agent 不知道会做错时**才进规则文件 | — |
| 启动、构建、测试命令变化 | README 的快速开始、规则文件的命令清单、CI 配置、贡献指南 | 旧命令全文；`npm run`、`make` |
| 端口、地址、依赖版本变化 | README、docs 的部署/开发说明、.env.example、docker-compose 文件 | 旧端口号、旧版本号 |
| 配置项增删 | 配置说明文档、.env.example、规则文件 | 配置键名 |
| 接口或数据结构变化 | API 文档、调用方代码、示例请求、类型定义的注释 | 字段名、路由路径 |
| 目录结构调整 | README 的结构图、规则文件里的路径约定 | 旧路径 |
| 新的约定或踩坑 | 规则文件（下一个 Agent 不知道就会做错的才写） | — |
| 一个决策完成（deciding-and-executing） | `.decision/` → docs/decisions/；复盘教训 → 规则或 Gotchas | — |
| 发布 | CHANGELOG、README 的版本说明、部署文档 | 版本号 |

## 搜索技巧

- 先用 git 看改了什么：`git diff --stat <基准>`、`git diff <基准> -- <文件>`。
- 有 `rg` 时优先用它全仓搜索，例如 `rg -n "旧名字" --glob '!CHANGELOG*'`；没有就用 `grep -rn`。
- 数字型事实（端口、版本、数量）最容易在多处重复。搜到第二处时，考虑只留一处、其余改为链接。
- 历史类文件（CHANGELOG、docs/decisions/）里的旧名字是正确的历史，不改。

## 不需要同步的情况

- 纯内部重构，对外行为、命令、路径都没变：只需确认规则文件里的路径约定仍然成立。
- 只改了测试：通常不需要同步文档，除非测试命令变了。
- 用户明确说只同步某一部分：其他面在报告里标为"不在本次范围"，不擅自处理。
