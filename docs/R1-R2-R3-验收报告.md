# R1 → R2 → R3：阶段报告（本地候选）

> **注意：这是本地工程候选，而不是已完成真实 Agent 对照实证的稳定版本。** 不得把 R1 正反参考实现的分数当作 Agent 成绩。

## R1｜先建立可信基线

- 冻结基线：`deciding-and-executing v4.0.1 / closing-out v2.0.1`，独立的 R1-Evaluation-Kit 和 Prepared-Trials 不修改。
- 预注册三组：A 原生 Agent；B A+验收合同；C B+显式安装使用 Skills。严格区分 B-A 与 C-B；触发实验另测。
- 冻结输入 15 案例 × 3 组 = 45 Trial；原记录全部为 `NOT_RUN`，当前容器缺少 `claude` / `codex` CLI，也没有真实宿主 transcript 与费用记录。
- 本地评测器自检 7/7 PASS 可证明评分逻辑及正反样例；**无法证明任何一组 Agent 有性能增益**。
- 原始预注册阈值：没有新的越权损害；C-B 至少净胜 3 个配对案例；耗时中位开销不超过 30%；误完成率不增长。样本规模仅是探索性实验，不是统计显著性证明。

## R2｜针对证据盲区做最小增量

本候选仅增加两个**只读**操作和一份按需参考：

- `de.py preflight`：项目/分支、dirty 文件提示、计划验证命令枚举及已知风险提示；不修改代码，不检查凭据/硬件/依赖，不代替沙箱。
- `de.py coverage`：按决策卡的编号成功标准列出 covers 所关联的步骤证据与时效。状态是 `NO_COVERAGE` / `STALE` / `NEEDS_VERIFICATION` / `READY_FOR_INDEPENDENT_REVIEW`，最后一项**绝非成功标准 PASS**。
- 闸门 B 的 preview 增加待执行 Shell 命令的风险提示；提示是非穷尽模式匹配，**无命中并不意味着安全**。
- `references/verification-strategy.md` 提供交付物类别对应的验证建议，独立审查者需检查真实需求、设备/浏览器观察和源代码事实。
- 修订阶段②文档中 `if_then` / `first_step` 的审批绑定说明，使之与现有哈希实现一致。

## R3｜评测驱动的保守收敛

- 新增 8 项 R2 定向对抗测试，复跑 **8/8 PASS**：预检不执行命令、不更改用户文件；Gate B 显示风险；覆盖报表不将纯文字证据宣称为验证通过；过期 artifact 标明 STALE。
- 新增规范—源码一致性检查 **3/3 PASS**，防止经过多轮整改之后文档再次背离实际行为。单项变异检查（故意把审批字段写成“否”）被正确检出，1/1。
- 没有在当前环境启动原生 Claude Code/Codex 三组实验；因此 R3 **不能声称已实证改进真实 Agent 性能**，也不能解冻原始 R1 保留集来训练提示词。
- 没有引入第三方依赖，没有改动既有 `closing-out` 核心，实现保留原有 `de.py` 工作区与状态契约。
- 完整 **83 项 unittest 以 4 个独立分片执行，21+21+21+20 项，四个分片均返回退出码 0**。本次未重复执行耗时更长的 `dev/release_check.py` 汇总命令；其组成条件（结构验证、源码与安装包、外层 ZIP、静态审计、全部测试）均单独复核，详见交付证据。

## 操作者接力

1. 保留 R1 预注册实验与评分器在 Agent 可访问目录之外；使用隔离 HOME 或容器，避免全局 Skills 污染 A/B 组。
2. 完成 45 条真实 Trial，保存原始 transcript、宿主模型版本、干预、时间、成本，以及独立审查记录；未知值用 `null`。
3. 先冻结 R1 实际结果，再使用未用于开发的任务复测本候选；不要将新的候选与 v4.0.1 数据混在一个实验组里。
4. 若 C-B 未达到预注册收益阈值，应考虑减少规则而不是继续添加提示词。
